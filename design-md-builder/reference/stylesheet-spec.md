# The stylesheet

One file, `assets/<prefix>-brand.css`. It packages the design system as a
small, bounded vocabulary of tokens and classes for pages that cannot import
the real components.

## Header comment

Open with a block comment that says:

- what the file is for (pages made outside the main codebase);
- every source file it was copied from, with the date those were generated;
- "Nothing here is invented.";
- "Do not edit this file to make one page work. Change design.md, or use a
  page-owned `<prefix>-custom-*` / `<prefix>-viz-*` class."

## Tokens

Declare every token on `:root` as `--<prefix>-*`. Each value is copied from a
source, and a comment above each group names which one.

| Family | Names |
| --- | --- |
| Type family | `font-sans`, `font-serif` (only if the brand has one), `font-mono` |
| Type size | `type-xs` up the real scale. Use the source's step count, not a guess |
| Weight and leading | One token per weight the system actually uses, one per line height |
| Space | The source's own step names, e.g. `space-100`, `space-200` |
| Radius | The source's scale, plus `radius-full` |
| Shadow | Only the steps that exist |
| Containers | `container-reading`, `container-page`, `container-wide` |
| Surface and text | `surface`, `surface-neutral`, `surface-contrast`, `surface-input`, `text-primary`, `text-secondary`, `text-on-contrast`, `text-disabled` |
| Border and focus | `border-subtle`, `border-default`, `border-strong`, `focus` |
| Brand and action | `brand`, `action`, `action-hovered`, `action-active`, and `accent` if one exists |
| Status | `color-` and `surface-` for info, success, warning, error |
| Link | `link`, `link-hovered`, `link-visited` |
| Data | `chart-1` to `chart-6` |

Rename semantic roles to these generic names so design.md reads the same for
every brand, and record the source name of each in a comment. Leave out any
token the sources do not have; never fill it.

## Themes

Ship light and dark at minimum. Dark values come from the source's dark theme,
never from inverting light. Apply dark under
`@media (prefers-color-scheme: dark)` and under an explicit attribute such as
`[data-theme="dark"]`, with a matching `[data-theme="light"]` override. Set
`color-scheme: light dark`. No visible theme control.

## Primitives

Show this list to the user, with the prefix applied, before writing any CSS.
Drop groups for page kinds the file does not cover; add a primitive only when
a source component or a usage count supports it.

- **Shell:** `shell`, `page`, `skip-link`, `header`, `identity`, `wordmark`,
  `doc-meta`, `meta-item`, `footer`.
- **Opening:** `opening`, `opening-claim`, `opening-proof`, `opening-context`.
- **Layout:** `section`, `section-head`, `reading`, `flow`, `stack`,
  `cluster`, `grid` (12 columns), `split`, `band`, `col-4`, `col-6`, `col-8`,
  `col-12`.
- **Type roles:** `display`, `title`, one `heading-<size>` per real heading
  step, `lede`, `body`, `compact`, `label`, `meta`, `caption`, `mono`,
  `numeric`, `visually-hidden`. Map each role to the source's text styles.
- **Evidence:** `note`, `formula`, `sources`, `stat-strip`, `stat`,
  `stat-label`, `stat-value`, `stat-detail`, `table-wrap`, `card`,
  `card-head`, `card-title`, `card-body`, `callout` plus one modifier per
  status, `tag`.
- **Charts:** `chart`, `chart-header`, `chart-viewport`, `chart-caption`,
  `legend`, `bar-list`, `bar`, `bar-label`, `bar-value`, `bar-track`,
  `bar-fill`, `chart-axis`, `chart-gridline`, `series-stroke`,
  `series-fill`, `data-point`, `direct-label`, `chart-value`, `annotation`,
  `annotation-line`, `series-1` to `series-6`.
- **Controls:** `button` plus the source's real variants and sizes, `field`,
  `field-label`, `field-control`, `field-help`, `field-error`, `calculator`,
  `calculator-inputs`, `calculator-output`, `result`, `result-label`,
  `result-value`, `result-detail`.

For an app-screen kind, add an app layout (`app`, `sidebar`, `main`,
`toolbar`) and the components the usage scan ranks highest that are missing
above (tabs, navigation, a data list).

For a marketing kind, add:

- **Hero:** `hero`, `hero-lede`, `hero-actions`. Actions centre vertically, so
  a caption beside a button lines up with it.
- **Sections:** `section`, `section-head`, `band`.
- **Feature list:** `feature-list`, `feature`, `feature-title`,
  `feature-body`. A short list of what the product does, as rows divided by
  hairlines. Without it, agents either build a three-card grid or style their
  own list and get the spacing wrong.
- **Inline form:** `inline-form`, `inline-form-row`. One input with its button
  beside it, the button lined up with the input rather than with the note
  below. Stacks on a phone with the button at full height. Without it, every
  landing page invents its own sign-up row.

The smoke test cannot reveal a missing primitive, because it only uses
classes that exist. Think through the page kinds chosen and ask which common
pattern on them has no class yet.

## Craft rules the CSS must enforce

- The default `button` uses the action colour. Variants map to the source's
  real button variants, sizes and min-heights.
- Spacing rhythm follows the steps the usage scan says are used most.
- Type uses only the source's weights and line heights. Letter spacing stays
  at the source's value.
- Tables: full width of their section, numeric cells and their headers right
  aligned via `[data-numeric]`, rows aligned to the first baseline.
- `bar-list` is one grid so every track shares the same start and end lines.
- Grid and flex children get `min-width: 0`. Nothing overflows at 375px.
- Visible focus on every control, from the `focus` token.
- A print block that drops shadows and keeps the page on white.

## Bugs that only rendering catches

The first three turned up in the first stylesheet built this way, the last two
in the second.

1. An SVG axis class that sets both `stroke` and `fill` paints a stroke round
   the axis labels. Split the line rule from a `text.<prefix>-chart-axis` rule.
2. A `margin: 0` reset on type classes, declared later at equal specificity,
   silently removes the gap a `flow` container adds. Scope the flow rule to
   the page element so it wins.
3. Two primitives that nest (a formula inside a calculator output) given the
   same surface colour make the inner one disappear. Give them different
   surfaces.
4. A base rule that styles plain elements inside the shell (`.shell h1`,
   `.shell a`) ties on specificity with the design system's own classes and
   wins by loading later: a hero title shrinks, a link-styled button gets link
   colour on its own fill. Wrap every such rule in `:where()` so any class
   beats it.
5. A bar fill or track written as a `<span>` is inline, so its height does
   nothing and no bar shows. Set `display: block` on both.
